# Changelog

All notable changes to **OreSim by krwawiec** (called "OreSim by gumark" up
to 1.1.0, when gumark maintained it) are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.3.0] — 2026-10-16

Minecraft version: **26.1.2** (Fabric). Java: 25+

### Added
- **Render styles** in the `/oresim` menu: *Veins* (default; each vein drawn
  as one shape with only its outer edges and faces), *Boxes* (a see-through
  filled box per block, slightly inset) and *Outlines* (the previous look).
- **Fill** (off/low/medium/high), **line thickness** and **range** (16/32/48
  blocks or all) settings.
- **Show all / Hide all** buttons for the ore toggles.
- **O key** opens the menu (rebindable); the first time the overlay is turned
  on, a chat hint mentions it.

### Changed
- Renamed to **OreSim by krwawiec**, now maintained by krwawiec; jars are
  named `oresim-by-krwawiec-<version>-mc<minecraft>.jar`. The mod id stays
  `oresim`, so existing configs and saved data keep working.
- Ore toggles and display settings are saved in `config/oresim-settings.json`
  instead of resetting on every restart.
- Coal and lapis colours brightened so they stay visible as a fill.

## [1.2.0] — 2026-10-16

Fork of gumark/fabric-oresim. Minecraft version: **26.1.2** (Fabric). Java: 25+

### Added
- **Auto-mining with Baritone** (optional dependency, Baritone 1.18.0):
  `/oresim mine [ores…]` and `/oresim stop`. Mines predicted ores (which
  Baritone's `#mine` can't see behind anti-xray) and visible exposed ores,
  breaks ores within reach in place (only with a tool that gets the drop),
  picks up drops, and tunnels onward when nothing is left in range.
- **Mined and disproven ores are remembered**: predicted ores that turn into
  air are marked mined; exposed predictions that still aren't the ore after 2
  seconds are marked wrong. Both are hidden from the overlay and the miner and
  saved per server, seed and dimension in `config/oresim-mined.json`.
  `/oresim clearmined` resets them.
- **Accuracy tester** (`src/tester`, development only): runs the simulation
  against a world generated by a real dedicated server and reports precision
  and recall per ore type and per correction (`gradlew runAccuracyTest`).

### Fixed
- Startup crash on 26.1.2: `HeightContextMixin` required a `getSeaLevel()`
  call that 26.1.x's `WorldGenerationContext` doesn't make.
- Crash when turning the overlay on with 26.1.2: ancient debris
  (`ScatteredOreFeature` isn't an `OreFeature` subclass there) was rejected.
- Prediction accuracy (all ores 79–83% → 96.5–99.5% precision behind
  anti-xray, measured on three seeds):
  - vein placement checks an estimate of vanilla's `OCEAN_FLOOR_WG` terrain
    height instead of `MOTION_BLOCKING`, which counted water and leaves;
  - ores placed earlier in a chunk block later veins, in vanilla feature order;
  - chunks are only simulated once their neighbours are loaded;
  - mined-out ores count as ore when re-simulating, keeping the random
    sequence in sync;
  - biomes are looked up by block position like vanilla's `BiomeFilter`
    (block coordinates were passed as biome-cell coordinates);
  - sculk, moss and dripstone count as the stone they replaced.

### Changed
- The simulation is in its own class (`OreSimulator`), shared by the client
  overlay and the accuracy tester.
- Build outputs are no longer committed; jars are published as releases.

## [1.1.0] — 2026-10-09

Minecraft versions: **26.3**, **26.2**, **26.1.2** (Fabric)

Java: 25+

### Added
- **Per-server seed memory** — seeds set with `/setoresimseed <seed>` are
  remembered per server address in `config/oresim-server-seeds.json`.
  Rejoining the same server restores the seed automatically (announced in
  chat); setting it twice is unnecessary. The seed is persisted on
  disconnect and dropped from the session, so it can never carry over to a
  different server. Singleplayer worlds are unaffected — the real seed is
  still read from the world itself.

### Performance
- **Render-path overhaul** — simulated ore positions are bucketed per ore
  type into flat packed-position arrays at simulation time, so each frame
  only walks plain arrays: no per-ore map entries, EnumSet lookups, or
  style allocations (`GizmoStyle` objects are built once at startup).
  Toggles are snapshotted once per frame, disabled types skip their whole
  group, and empty chunks early-out on a cached box count.
- **Fewer duplicate boxes** — overlapping veins from same-type ore
  placements (e.g. the three iron placements) are deduplicated, trimming
  total box count.
- **Simulation micro-cut** — the per-biome ore fallback no longer streams
  the ore map on every placement attempt (a path hit thousands of times
  per chunk).
- **Simulation lag cuts** — simulation bounded to the rendered 5-chunk
  diamond; removed the 3×3-neighbor full biome-palette rescan; chunks are
  evicted from the cache on unload; unsimulated in-range chunks are swept
  when the player crosses a chunk boundary; per-dimension ore list built
  once per reload; per-type gizmo styles cached.

### Fixed
- `/oresim` GUI no longer closes itself immediately (the screen is opened
  on the next tick instead of inside the chat submit path).
- Startup crash from the mixin config listing mixins that did not exist
  for the target Minecraft generation (per-generation mixin lists).

### Changed
- Fluid/water-lava overlay removed entirely — it was the main lag source
  and is not seed-predictable anyway.
- Overlay renders purely from the world seed: every simulated ore is drawn
  through walls even if the real block is visible, and the client world is
  never consulted, so anti-xray fake blocks can neither suppress nor fake
  boxes. (Earlier the overlay tried to hide ores already visible to the
  player; that behavior was replaced.)
- Jars are named with the mod and Minecraft versions, e.g.
  `oresim-by-gumark-1.1.0-mc26.3.jar`.
- Build is parameterized per Minecraft target
  (`gradle build -Pmc=26.2 -Pfapi=0.161.0+26.2`), with a compat layer
  covering the 26.3 and 26.2/26.1.2 API generations; sources and mixin
  configs are split per generation.
- Multi-version support: 26.2 and 26.1.2 jars ship alongside 26.3.

## [1.0.0] — 2026-10-01

Minecraft version: **26.3** (Fabric)

### Added
- Seed-based ore prediction: simulates vanilla ore decoration per chunk
  from the world seed and renders the results as boxes through walls.
- `X` key toggle for the overlay.
- `/setoresimseed <seed>` to set the world seed on multiplayer servers
  (vanilla seed parsing: numeric literal or text hashed like the vanilla
  world-creation field).
- `/oresim` GUI with per-ore-type toggles (coal, iron, gold, redstone,
  diamond, lapis, copper, emerald, quartz, ancient debris).
- Ported the OreSim module from meteor-rejects to a standalone Fabric mod
  for Minecraft 26.3.
